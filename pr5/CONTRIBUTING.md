# Правила совместной разработки

## Ветки

- Не отправлять коммиты напрямую в `main` и `develop`.
- Для задачи создавать ветку от актуальной `develop` в формате `feature/<номер-задачи>-<краткое-имя>`.
- Для исправления использовать `bugfix/<номер-задачи>-<краткое-имя>`.
- Для подготовки выпуска использовать `release/<версия>`, для срочного исправления опубликованной версии — `hotfix/<номер-задачи>-<краткое-имя>`.
- Имена веток и коммитов писать латиницей; коротко отражать суть изменения.

## Коммиты и Pull Request

Делать небольшие коммиты с одним смысловым изменением. Рекомендуемые префиксы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`. PR должен ссылаться на Issue, описывать изменение и способ проверки. Перед запросом ревью обновить ветку от целевой ветки и убедиться, что обязательные проверки завершились успешно.

## Слияние

Изменения в `develop` и `main` принимаются только через PR. Автор PR не одобряет собственные изменения. Для слияния необходимо одобрение Tech Lead (или назначенного проверяющего) и отсутствие блокирующих замечаний. Используется `Squash and merge`; после слияния ветка задачи удаляется.

Изменения `develop` выпускаются в `main` через `release/<версия>`. Ветки `hotfix/*` начинаются от `main`; после слияния исправление также переносится в `develop`.
